Powering the New Microsoft Agent Framework with Gemini 3.x

Saverio Terracciano
7 min read
·
Feb 25, 2026

--

How to bring Google’s latest models into the new .NET Agentic ecosystem

The year has started, and I wanted to share what I am currently focusing on: Agent Frameworks. Although I really enjoy building with Google’s Agent Development Kit (ADK), my primary background is in .NET. Since my team relies heavily on the .NET stack for both internal and client projects, I have been exploring the new Microsoft Agent Framework.

If you’ve been building AI agents in .NET in the past year, you know the struggle: AutoGen gave us great multi-agent support, while Semantic Kernel gave us enterprise stability, but moving from prototype to production was tough due to fragmented APIs. Developers asked for both capabilities in one package. Enter the new Microsoft Agent Framework and Microsoft.Extensions.AI. It’s an open-source, unified, standardized foundation to finally build production-ready AI apps (A few days ago officially moved from Pre-release to Release Candidate).

At first glance, it would be a perfect fit for many of the scenarios we deal with at my company. But there is a small catch.

Out of the box, the new framework heavily favors OpenAI models. It’s incredibly easy to spin up an OpenAI client and get going. That’s great to start, but as a personal preference, I love Gemini models. Even more so, we have internally benchmarked them against other frontier models in several use cases for the past year, and we are quite happy with the performance/price, so we’d like to have the possibility to use them if we were to adopt Microsoft’s Agent Framework for future projects.

The beauty of the Microsoft.Extensions.AI library is that it revolves around a unified interface: IChatClient. If we can implement that interface, we can plug Gemini into any modern Microsoft Agent application. As the product is still not fully mature, there isn’t a full documentation on how to deliver a custom implementation of the relevant interface, so with this article, I’ll help you understand how it works, and how to do it.

Let’s break down how to build this, step by step.

[NOTE] Before proceeding it would be beneficial for you to be familiar with Gemini’s REST API Request/Response structure (if you are not, you can read my previous articles [1], [2] and experiment via Google AI Studio) and the overall standard flow of Microsoft Agent Framework, which you can get started with [here]

Building the Gemini 3.x Chat Client

To make Gemini play nice with the Microsoft Agent Framework, we need to create a class that implements IChatClient and calls Google’s Gemini API under the hood.

Instead of dumping a massive wall of code on you, let’s look at it in manageable chunks.

1. Setup and Initialization

Assuming we have created a new project, a Console App in this example, first thing we want to do is to import the Microsoft.Agents.AI Nuget package, either via the Package Manager Console or Package Manager GUI.

First, we create and set up our class (that will inherit from IChatClient), inject our API key, and configure our HttpClient to point to Google’s generative language API. We also initialize the ChatClientMetadata which the Microsoft framework uses to identify the underlying model. Notice that we are defaulting the model parameter to the new “gemini-3.0-flash”.

namespace SimpleGeminiAgent;
using Microsoft.Extensions.AI;
using System.Net.Http.Json;
using System.Runtime.CompilerServices;
using System.Text.Json;
using System.Text.Json.Serialization;

/// <summary>
/// Direct implementation of IChatClient for Google's Gemini API
/// </summary>
public class GeminiChatClient : IChatClient
{
    private readonly string _apiKey;
    private readonly string _model;
    private readonly HttpClient _httpClient;
    private const string BaseUrl = "https://generativelanguage.googleapis.com/v1beta/models";
    private readonly ChatClientMetadata _metadata;
    // Updated to default to the new Gemini 3.0 Flash model
    public GeminiChatClient(string apiKey, string model = "gemini-3.0-flash")
    {
        _apiKey = apiKey ?? throw new ArgumentNullException(nameof(apiKey));
        _model = model;
        _httpClient = new HttpClient();
        _metadata = new ChatClientMetadata("Gemini", new Uri(BaseUrl), _model);
    }

2. Getting a Response

Next, we need to implement the core method: GetResponseAsync. This method takes the standardized ChatMessage collection from Microsoft’s framework, formats it into a schema that Gemini understands, sends the POST request, and parses the result back into a format Microsoft expects (ChatResponse).

public async Task<ChatResponse> GetResponseAsync(
        IEnumerable<ChatMessage> chatMessages,
        ChatOptions? options = null,
        CancellationToken cancellationToken = default)
    {
        // We will define BuildRequest in a moment
        var request = BuildRequest(chatMessages);
        var url = $"{BaseUrl}/{_model}:generateContent?key={_apiKey}";

        var response = await _httpClient.PostAsJsonAsync(url, request, cancellationToken);
        response.EnsureSuccessStatusCode();
        var result = await response.Content.ReadFromJsonAsync<GeminiResponse>(cancellationToken);
        if (result?.Candidates == null || result.Candidates.Count == 0)
        {
            throw new InvalidOperationException("No response from Gemini API");
        }
        var content = result.Candidates[0].Content?.Parts?.FirstOrDefault()?.Text ?? string.Empty;
        return new ChatResponse([new ChatMessage(ChatRole.Assistant, content)])
        {
            CreatedAt = DateTimeOffset.UtcNow
        };
    }

3. Handling Streaming and Infrastructure

The IChatClient interface also requires a streaming method and a service locator method. For this simple implementation, we can wrap our standard response in an async enumerable to satisfy the streaming contract and return our metadata when requested.

public async IAsyncEnumerable<ChatResponseUpdate> GetStreamingResponseAsync(
        IEnumerable<ChatMessage> chatMessages,
        ChatOptions? options = null,
        [EnumeratorCancellation] CancellationToken cancellationToken = default)
    {
        var completion = await GetResponseAsync(chatMessages, options, cancellationToken);

        foreach (var message in completion.Messages)
        {
            if (message.Text != null)
            {
                yield return new ChatResponseUpdate
                {
                    Contents = [new TextContent(message.Text)],
                    Role = message.Role,
                    CreatedAt = DateTimeOffset.UtcNow
                };
            }
        }
    }
    public object? GetService(Type serviceType, object? serviceKey = null)
    {
        return serviceKey is not null ? null :
            serviceType == typeof(ChatClientMetadata) ? _metadata :
            serviceType?.IsInstanceOfType(this) is true ? this :
            null;
    }
    public void Dispose()
    {
        _httpClient.Dispose();
    }
}

4. The Payload and the Role Mapping Pain Point

Now for the crucial part: converting Microsoft’s message history into Gemini’s format.

[PAIN POINT] The Microsoft.Extensions.AI namespace uses standard abstractions for roles, typically identifying them as system, user, and assistant. However, Gemini handles roles strictly as user and model. If you pass “system” or “assistant” blindly in the main message array, the Gemini API will reject the request.

To fix this, we map assistant to model, and map system to user (since Gemini processes system instructions separately or as the primary user context in simple setups).

private static GeminiRequest BuildRequest(IEnumerable<ChatMessage> chatMessages)
    {
        var contents = new List<GeminiContent>();

        foreach (var message in chatMessages)
        {
            var role = message.Role.Value switch
            {
                "user" => "user",
                "assistant" => "model",
                "system" => "user", // Gemini doesn't have a system role in the 'contents' array
                _ => "user"
            };
            contents.Add(new GeminiContent
            {
                Role = role,
                Parts = [new GeminiPart { Text = message.Text ?? string.Empty }]
            });
        }
        return new GeminiRequest { Contents = contents };
    }

5. Data Models

Finally, we just need a few private classes at the bottom of our file to handle the JSON serialization and deserialization for Google’s specific REST API schema.

// Gemini API request/response models
    private class GeminiRequest
    {
        [JsonPropertyName("contents")]
        public List<GeminiContent> Contents { get; set; } = [];
    }

    private class GeminiContent
    {
        [JsonPropertyName("role")]
        public string Role { get; set; } = string.Empty;
        [JsonPropertyName("parts")]
        public List<GeminiPart> Parts { get; set; } = [];
    }
    private class GeminiPart
    {
        [JsonPropertyName("text")]
        public string Text { get; set; } = string.Empty;
    }
    private class GeminiResponse
    {
        [JsonPropertyName("candidates")]
        public List<GeminiCandidate> Candidates { get; set; } = [];
    }
    private class GeminiCandidate
    {
        [JsonPropertyName("content")]
        public GeminiContent? Content { get; set; }
    }
}

Spinning Up Your First Gemini Agent

Now that we have our GeminiChatClient, utilizing the new Microsoft.Agents.AI namespace feels like a walk in the park. This abstracts away all the heavy lifting of maintaining conversation history and context!

Let’s look at our Program.cs.

1. Wiring it up

We simply instantiate our custom client with our Gemini API key, pass it into a ChatClientAgent, and define some basic instructions.

namespace SimpleGeminiAgent;
using Microsoft.Agents.AI;
using Microsoft.Extensions.AI;

internal class Program
{
    static async Task Main(string[] args)
    {
        var apiKey = Environment.GetEnvironmentVariable("GEMINI_API_KEY") 
            ?? throw new InvalidOperationException("GEMINI_API_KEY environment variable is not set.");
        
        Console.WriteLine("Hello! I'm a simple AI assistant powered by Gemini 3.0 and the Microsoft Agent Framework.");
        Console.WriteLine("Chat with me! Type 'exit' or 'quit' to end the conversation.\n");
        // Create our custom Gemini chat client targeting 3.0 Flash
        IChatClient chatClient = new GeminiChatClient(apiKey, "gemini-3.0-flash");
        // Create an AI agent with the chat client
        AIAgent agent = new ChatClientAgent(
            chatClient,
            instructions: "You are a helpful AI assistant. Be concise and friendly in your responses.",
            name: "SimpleAssistant");

2. Managing the Session

To give our agent memory, we initialize an AgentSession. Then, we drop into a standard while loop, grabbing user input and passing it to agent.RunAsync. The session object automatically manages appending our messages and the model’s responses to the history for us.

// Start a new session
        AgentSession session = await agent.GetNewSessionAsync();

// Main chat loop
        while (true)
        {
            Console.Write("You: ");
            string? userInput = Console.ReadLine();
            if (string.IsNullOrWhiteSpace(userInput))
            {
                continue;
            }
            if (userInput.Equals("exit", StringComparison.OrdinalIgnoreCase) || 
                userInput.Equals("quit", StringComparison.OrdinalIgnoreCase))
            {
                Console.WriteLine("Goodbye!");
                break;
            }
            try
            {
                var response = await agent.RunAsync(userInput, session);
                Console.WriteLine($"Assistant: {response}\n");
            }
            catch (Exception ex)
            {
                Console.WriteLine($"Error: {ex.Message}\n");
            }
        }
    }
}

Hit run, and just like that, you have a blazing fast, memory-aware Gemini 3.x agent running natively on .NET’s newest AI framework.

An Excellent Alternative: MSCC Generative AI

While I always encourage developers to write their own HTTP implementations at least once to understand the mechanics under the hood, you don’t always have to reinvent the wheel for production apps.
You can reserve the knowledge you acquire for specific scenarios/implementations.

In this specific scenario, if you want a more robust, fully featured library that handles Gemini integrations beautifully in .NET, I highly recommend checking out the Mscc Generative AI framework. It’s actively maintained by a fellow GDE and good friend of mine, Jochen Kirstätter, and it takes all the pain out of managing file uploads, advanced model configurations, system instructions, and embeddings. It’s a fantastic, production-ready NuGet package to handle the Google side of things before you pipe it into your Microsoft Agents.

There are, however, many other models (e.g. self-hosted Gemma model, a proprietary fine-tuned model, etc.) that are not directly supported, and you can apply the same methodology you learnt in the article to create an implementation for them.

Key Takeaways

  • Abstractions are your friend: Microsoft’s IChatClient is a massive leap forward for .NET developers wanting framework-agnostic AI code.
  • Role Mapping: Remember to map Gemini’s unique role structures to the standard roles expected by Microsoft.Extensions.AI.
  • Best of Both Worlds: You are no longer locked into a single ecosystem. You can build with C# and Microsoft’s robust architectures while utilizing Google’s incredibly capable Gemini 3.0 models.
